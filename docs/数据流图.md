# 校园失物招领 · 关键流程与数据流图

## 一、系统分层与数据流

```mermaid
flowchart LR
    U[用户操作<br/>点击 / 输入] --> A[app.js<br/>事件绑定与编排]
    A --> C[core.js<br/>纯业务逻辑]
    A --> S[store.js<br/>localStorage 持久化]
    S --> L[(浏览器 localStorage)]
    C --> R[render.js<br/>DOM 渲染]
    R --> V[界面更新]
    L --> A
    D[data.js 种子数据] --> S
```

- **core.js**：只做数据运算（搜索、筛选、状态机、校验、格式化），不碰 DOM 和存储，因此可被 Node 直接 `require` 做单元测试。
- **store.js**：唯一读写 localStorage 的地方，负责「首次写入种子数据、增改、持久化」。
- **render.js**：把数据变成 HTML，插入 DOM 前统一做 HTML 转义（防 XSS）。
- **app.js**：持有全局状态 `State`，接收用户事件、调用 core/store/render 完成一次交互。

## 二、核心业务流程图

```mermaid
flowchart TD
    Start([打开应用]) --> Init[store.load 读 localStorage]
    Init -->|为空| Seed[写入 8 条种子数据]
    Init -->|有数据| Render[渲染首页列表]
    Seed --> Render

    Render --> Browse[浏览 / 搜索]
    Browse --> Filter{按类型 / 类别 / 关键词筛选}
    Filter --> Render

    Render --> Detail[点击卡片 → 详情页]
    Detail --> Contact[联系发布者<br/>弹窗 + 一键复制]
    Detail --> Mark{信息状态?}
    Mark -->|进行中| MarkDone[标记已找到 / 已归还]
    Mark -->|已完成| Noop[提示无需修改]
    MarkDone --> Save[store.update 写回 localStorage]
    Save --> Render

    Render --> Publish[发布页填表单]
    Publish --> Valid{必填项校验}
    Valid -->|不通过| Toast[提示缺失项]
    Valid -->|通过| Add[store.add 新条目置顶]
    Add --> Render
```

## 三、状态机

```mermaid
stateDiagram-v2
    [*] --> 待认领 : 发布「招领」
    [*] --> 寻找中 : 发布「寻物」
    待认领 --> 已归还 : 发布者标记
    寻找中 --> 已找到 : 发布者标记
    已归还 --> [*]
    已找到 --> [*]
```

- 「招领」信息的完成态是 **已归还**，「寻物」信息的完成态是 **已找到**；
- 已完成状态不可再回退，标记后首页 / 详情 / 我的发布三处同步刷新。

## 四、核心函数说明

| 函数 | 所属文件 | 作用 |
| --- | --- | --- |
| `searchItems(items, kw)` | core.js | 名称/类别/地点/描述 多字段模糊匹配 |
| `filterByType / filterByStatus` | core.js | 类型（招领/寻物）、状态（进行中/已完成）筛选 |
| `markDoneStatus(item)` | core.js | 状态机转移，非法转移返回 `null` |
| `validateItem(fields)` | core.js | 名称/地点/联系方式必填校验 |
| `relativeTime(iso, now)` | core.js | ISO 时间 → 「刚刚 / n 分钟前」 |
| `Store.load / add / update` | store.js | 数据读写与持久化 |
| `Render.renderHome / renderDetail / renderMine` | render.js | 各页面 DOM 渲染 |
